LogStream

Distributed Log Analytics & Alerting Platform

A distributed log analytics platform designed to ingest, index, search and analyze massive volumes of application logs with low-latency queries.

gRPCBinary log ingestion

PostgreSQLMetadata such as alert rules and tenants

The Problem

Storing and searching terabytes of application logs in a relational database collapses under scan-heavy queries. A query such as WHERE message LIKE '%timeout%' against 100M rows can become a full table scan.

The Solution

LogStream inverts that model. Logs flow in as binary protobuf over gRPC, are inverted-indexed in Apache Lucene, and are queried through a purpose-built query language. PostgreSQL is retained for metadata rather than raw log search.

Log Producers→gRPC / Protobuf→Java Backend→Apache Lucene Index→Query Engine→Matching Logs + Facets

Key Engineering Features

gRPC Ingestion

Receives binary protobuf log traffic.

Lucene Indexing

Transforms logs into an inverted index designed for fast search.

Purpose-Built Queries

Supports queries such as level:ERROR AND service:billing-api AND response_time > 1000.

Metadata Separation

PostgreSQL stores metadata such as alert rules and tenants, not raw log search data.

Architecture

The ingestion path and search path are separated conceptually: gRPC handles incoming log traffic, the Java/Spring Boot backend processes it, Lucene provides the search index, and PostgreSQL stores supporting metadata.

Implementation

Log → protobuf → gRPC → Java/Spring Boot → Lucene index → query → exact matching lines + facets/histograms

Fast search starts with the right data model.
